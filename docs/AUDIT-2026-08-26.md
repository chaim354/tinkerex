## Read this before you plan from the list

**The 69 is inflated. The honest number is about 34.**

The review brief capped each lane at "at most two findings" with a `maxItems: 2` schema, and that
created quota pressure. Lanes said so in their own notes — one recorded that it judged something
"below the threshold … rather than manufacturing it into a finding"; another closed with "this is a
medium-confidence recommendation, not an obvious win."

The proof: when the cap was removed for the nine rows added late, and those lanes were told
explicitly that *one finding, or zero, is a valid answer*, the yield fell from ~2 per lane to
**7 across 9 lanes, with 3 skips**.

This is a codebase whose comments argue at length for most of its current shapes. Four findings were
rejected outright and twelve narrowed. **Do not treat the raw list as a backlog** — §14e's "a stale
open-list is worse than none" applies directly.

## 3. Corrections to the coordinator's own verdicts

Five independent passes audited this audit and overturned six of my verdicts. Recorded because a
review that only confirms itself is not a review, and because **a later reader who trusts the wrong
ones will act on them**.

1. **I promoted a finding on a claim the code contradicts.** I wrote that browser-imported files are
   "stored as role `other`". False — `importer_controller.js:122` posts only `{node_id, cover}`, and
   the server derives the role authoritatively at `models/attachments_controller.rb:23`. The
   finding's own risks section said so. **S21-1 demoted.**
2. **I accepted a finding whose central sentence is false.** S22-1 claims nothing states that only
   `name` has a SQL folder ordering; `files_controller.rb:886` states it, with a per-sort argument,
   fourteen lines above the code critiqued. **Narrowed to its one-token residual.**
3. **I named the wrong door.** The missing `MAX_BYTES` cap is not reachable via the preview job —
   that guards on `MAX_PREVIEW_BYTES`. The unguarded caller is `ExtractPdfMetadataJob:33`.
4. **I over-applied a cross-repo caution.** Correct for S15-1's Project half; wrong for the Task
   half — `v1/maker/tasks_controller.rb:41` does not permit `completed_at`.
5. **I asserted a false coverage claim.** My contract said every file under `test/` was claimed by
   exactly one row. **256 test files (~51,000 lines — larger than all of `app/`) were claimed by
   about 20.** I also excluded `vendor/javascript/**` as "the vendored CodeMirror bundle" when
   three.js is 79,617 of its 87,351 lines and CodeMirror is 72. Both retracted; nine rows added and
   audited (S37–S45).
6. **I nearly propagated an agent's error.** The ranking pass claimed dropping `nodes.updated_seq`
   would leave `PREFIX_INDEX_EXEMPTIONS` vacuous. `index_nodes_on_user_id` is a strict prefix of
   **five** composites, not one — the exemption stays live. Retracted before it reached the ranking.

Two lane-side numbers were also wrong and are corrected in place in the findings file: **S36-1's
"exactly five hits" is seven**, and **S09-2's "single grep hit" is one of 25** (23 `Dir.children`, a
JS DOM hit, and a live caller of a *different* model's association). Both conclusions survive.

## 4. Two things worth fixing that are not simplifications

- **A code comment claims a guard that does not exist.** `app/controllers/concerns/v1/authentication.rb:15-17`
  states that `test/v1_auth_parity_test.rb` "compares the two implementations and fails when they
  stop agreeing", and cites `test/engine_schema_test.rb` alongside. **Neither file exists.** §14j
  already records that nothing checks that agreement — so the comment contradicts CLAUDE.md on the
  one cross-repo obligation CLAUDE.md says is unguarded.
- **The production image has no equivalent of `ci/ensure-resvg.sh`.** CI warns loudly when a runner
  lacks resvg, precisely because an unavailable binary degrades silently to `unsupported`. Drop a
  `COPY` at `Dockerfile:155/159/163/173` and every file of that format renders unsupported forever
  with nothing red — this repo's dominant recorded failure shape. The right instrument is a smoke
  check against the built image, not a Dockerfile-parsing unit test.

Also noted and **not** promoted: `test/deploy_hygiene_test.rb:9` cites "Dockerfile:47 is `COPY . .`"
where the actual line is `57` (the assertion itself is unaffected); and `Dockerfile:39`'s
`COPY Gemfile Gemfile.lock vendor ./` drops `vendor/`'s contents flat into `/rails/`.

## 6. Method, and what is not here

**Structure.** 45 bounded read-only lanes, one per subsystem, each given a file-exact boundary and
told to stay inside it. Then five independent passes auditing the audit: repository coverage,
duplication and ownership overlap, materiality and over-abstraction, schema completeness, and
dependency-aware ranking. Every finding was re-verified by the coordinator against the tree before
acceptance.

**What the schema pass checked.** All 536 evidence references were extracted and machine-checked:
zero out-of-bounds line numbers, zero fabricated in-repo paths, and no `validation` field naming a
test that does not exist. ~70 references were additionally opened by hand across 25 subsystems.

**Known gaps in the record itself**, recorded rather than silently fixed: the `category` field is
absent on 5 of 69 findings; `S13-2`'s `affected_files` lists 5 files where its own scope requires 24;
`S09-1` names a `db/cable_migrate` directory that does not exist and omits `config/cable.yml` and
`db/cache_schema.rb`; and `S21-1`, `S21-2`, `S25-1`, `S25-2` record absolute worktree paths that stop
resolving once this branch lands.

**Not committed.** The raw lane transcripts and the intermediate `findings.json` / `findings.md`
dumps were session scratch and are gone. Everything load-bearing is in these two files.

**Not filed to Forgejo.** §11 makes the Forgejo instance the canonical record for arcs, written with
`bin/log`. This audit produced no code change, so it is not an arc; past audits live in `docs/` by
the same convention (`AUDIT-2026-07-30`, `-08-03`, `-08-19`, `SYSTEM-AUDIT-2026-07-28`). If you want
it tracked as open work, `bin/log open` is the door — that needs the vault and `forgejo.home`, and
was deliberately not done unasked.
