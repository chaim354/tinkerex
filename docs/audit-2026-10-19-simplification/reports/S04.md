## Opportunity 1: Parse each wire shape into ONE node-state value before applying it (ChangelogSync) — removes a shape-guessing applier whose resync arm silently drops every file's version, size and manifest
1. Verdict: recommend
2. Evidence:
   - `changelog_sync.rb:213-231` — one applier serves both wire shapes by guessing: `version ||= payload["version"]` (222); everything content-related sits inside `if version` (223); the manifest is `payload["manifest"] || @current_manifest` (230).
   - `changelog_sync.rb:183-188` — the changes path smuggles the ENTRY-level manifest in through instance state: `@current_manifest = entry["manifest"]` / `upsert(node, deleted: node["deleted"], version: entry["version"])` / `@current_manifest = nil`, with the comment that /v1/tree is where the manifest "IS nested" (185).
   - `changelog_sync.rb:166` — the resync arm: `nodes.each { |n| upsert(n, deleted: false) }`, no `version:`.
   - `docs/sync-protocol.md:674-690` (the normative wire spec, §6) — a /v1/tree node carries `"version_id": "...", "size": 1048576, "manifest": [...]` FLAT on the node (679-680), with no `version` object; contrast /v1/changes at 619-620, where `version` and `manifest` are ENTRY-level.
   - Both real servers agree with the spec, not with the client: Rust `../tinkerex-sync/crates/tinkerex-sync/src/services/tree.rs:10-26` (`TreeNode { …, version_id, size, manifest, symlink_target }`, filled 68-77) vs `services/changes.rs:27-45` (`Change { node, version: Option<ChangeVersion>, manifest }`); and the Ruby server this class was written against on 2026-08-21 (`git show 08552a07^:engines/tinkerex-sync/app/services/sync/tree.rb`, `serialize`: `out[:version_id]`, `out[:size]`, `out[:manifest]`). The tree shape was flat before ChangelogSync existed (17094e8b).
   - The reference client models exactly two typed shapes converted into one apply input: `../tinkerex-client/client/sync-client/src/lib.rs:274-322` (`Change` vs `TreeNode`), `client/sync-engine/src/lib.rs:1298-1326` (`tree_node_to_sync`) and 1575-1606 (`change_to_sync`) → one `SyncNode` → `apply_remote`. ChangelogSync's header (`changelog_sync.rb:5-7`) claims to do "what `apply_remote` does in Rust" but collapsed the two conversions into one guessing `upsert`.
   - The only test of the resync arm uses a fake that shares the misunderstanding: `changelog_sync_test.rb:148-150` gives its tree node a nested `"version" => { "version_id" => "v1", "manifest_id" => "m", "size" => 9 }` — a key neither server has ever sent — and asserts `size == 9` (155). That is §14e's "a fake that shares the code's misunderstanding confirms it". The one test that fed REAL server output to ChangelogSync (`changelog_sync_test.rb:214-233`) skips on every leg (`skip … unless defined?(Sync)`, while `build_chunk_remote_test.rb:99-103` asserts Sync is never defined), and no journey test can reach a resync. The tree shape has no real-server coverage at all.
3. Current complexity or invalid states:
   - After a pruned-gap resync, every node is upserted with NO content fields: `current_version_id`, `size` and manifest rows stay as they were. A file created while the mirror was behind lands with `current_version_id: nil, size: nil` → `stat` says 0 bytes and `content_token: nil`, and `read`/`download` raise NotFound "no manifest" (`chunk_remote.rb:149-151`, `190-191`): a listed file 404s. A file whose content changed while behind keeps its OLD version id and size → `read`/`download` serve the OLD bytes (the old manifest rows are still mirrored and the server presigns any hash the user still owns), and previews stay keyed to the old token. Neither self-heals until that node's next `put` entry — a move/rename entry carries no version. Structure (parent/name/deleted) is repaired correctly; content is not.
   - The `@current_manifest` ivar is an implicit parameter passed through instance state, and `payload["manifest"]` — the arm meant for /v1/tree — is unreachable on both real shapes (tree: `version` is nil, so the block never runs; changes: the node payload has no manifest key).
   - Reachability: gated on `cursor < oldest_seq` (`changelog_sync.rb:149-152`). tinkerex-sync already ships `prune_changelog` (`gc.rs:200-205`, documented "A device whose cursor is below the new floor full-resyncs from the snapshot") with no caller yet. The day it is scheduled, every chunk_remote mirror that was behind is damaged as above, silently. Latent, not hypothetical.
4. Proposed representation and why it is simpler — one value, two constructors, one applier (the Rust client's shape):
   ```ruby
   NodeState = Data.define(:node_id, :parent_node_id, :name, :kind, :mode, :mtime, :deleted,
                           :symlink_target, :version_id, :size, :manifest) do
     # /v1/changes entry (§8.3): state under "node"; content ENTRY-level, only on a put whose
     # version still resolves. nil when the server sent no node (hard-removed).
     def self.from_change(entry)
       n = entry["node"] or return nil
       v = entry["version"] || {}
       new(node_id: n["node_id"], parent_node_id: n["parent_node_id"], name: n["name"], kind: n["kind"],
           mode: n["mode"], mtime: n["mtime"], deleted: !!n["deleted"], symlink_target: n["symlink_target"],
           version_id: v["version_id"], size: v["size"], manifest: entry["manifest"])
     end

     # /v1/tree node (§8.4): live by definition; content FLAT on the node.
     def self.from_tree(n)
       new(node_id: n["node_id"], parent_node_id: n["parent_node_id"], name: n["name"], kind: n["kind"],
           mode: n["mode"], mtime: n["mtime"], deleted: false, symlink_target: n["symlink_target"],
           version_id: n["version_id"], size: n["size"], manifest: n["manifest"])
     end

     def live_file? = !deleted && kind == "file" && parent_node_id.present?
   end

   def apply(s)   # replaces upsert(payload, deleted:, version:) and @current_manifest
     row = @user.nodes.find_or_initialize_by(node_id: s.node_id)
     row.assign_attributes(parent_node_id: s.parent_node_id, name: s.name, kind: s.kind,
                           mode: s.mode, mtime: s.mtime, deleted: s.deleted)
     if s.version_id   # absent on mkdir/move/delete and on a put whose version was pruned: keep the old one
       row.current_version_id = s.version_id
       row.size = s.size
       store_manifest(s.version_id, s.manifest)
     end
     row.symlink_target = Base64.decode64(s.symlink_target) if s.symlink_target
     row.save!
   end
   ```
   `apply_page`: `if (s = NodeState.from_change(entry))` → `apply(s)`; `@nudge_parents << s.parent_node_id if s.live_file?`; else the unchanged hard-removed branch. `full_resync`: `nodes.each { |n| apply(NodeState.from_tree(n)) }`.
   Simpler because each wire shape is read in exactly one place, by keys it actually has; the applier has no shape knowledge, no ivar side channel, no `deleted:`/`version:` parameters and no `||` guesses. This is not new branching behind a type: it deletes two guesses, one of them wrong.

   2. `test/services/file_layer/chunk_remote/changelog_sync_test.rb` — correct the fake tree nodes (148-150, 164-165, 184-186) to the §8.4 flat shape; add the tests in 7.
   3. Optional: one test in `test/integration/chunk_remote_journey_test.rb` pinning the REAL /v1/tree shape.
6. Regression risks and migration concerns:
   - Data: none, no migration or backfill — a resync has never been reachable in production (nothing prunes), so no live mirror carries this damage.
   - Must preserve exactly: (a) a `put` entry whose version was pruned carries no version → leave `current_version_id` alone, never null it (`if s.version_id`); (b) `store_manifest`'s delete-then-insert idempotency and its `blank?` early return; (c) the no-node-payload branch; (d) the nudge is fed by `apply_page` ONLY — `docs/invariants/project-intake.md:319-326` ("deliberately not fed by `full_resync`"): collect at the call site, never inside `apply`; (e) `deleted` comes from the change node, and is false for a tree node.
   - Backend legs: production code runs on chunk_remote only. ChangelogSyncTest runs on fakes on all three legs, so new unit tests keep the three run counts identical; a journey test skips (a skip still counts as a run) off chunk_remote.
   - Once the resync is correct, two adjacent behaviours start to matter (out of this scope, flag them): the sweep is a single `where.not(node_id: seen)` over every live node id (`changelog_sync.rb:173`, a NOT IN of the whole library), and `if seen.any?` skips the sweep entirely when the server lists no live nodes.
   - Leaves the empty-manifest defect (below) as it is; `NodeState` makes `manifest: []` (known empty) vs `nil` (no content in this entry) explicit at the boundary, which a later fix can use.

## Considered and rejected
- One helper for the four `Transport.new(base_url: ENV.fetch("CHUNK_REMOTE_URL"), …)` sites (`chunk_remote.rb:513`, `remote_changelog_pull_job.rb:125-126`, `sync_grant.rb:31`, `provisioning.rb:129-138`), or having the job call the adapter's `refresh!`. The part that varies, and the part that leaked in Arc C (twice, "one caller over"), is the TOKEN policy: provision-on-demand in the adapter; skip-unprovisioned in the job, by design (`remote_changelog_pull_job.rb:61-70`); bootstrap-then-sibling in SyncGrant; the operator credential in Provisioning. A helper would centralise only the URL read. That is a line-count change.
- Deferring mkdir/delete/undelete/finalize the way `move` is deferred, to make `#batch` uniform — §14a invariant: each hands back state read from the row the pull writes (`chunk_remote.rb:266-284`).
- Memoising the per-user transport (ivar or `Thread.current`) — §14a invariant, mutation-checked by `transport_isolation_test.rb`.
- Replacing the `is_a?(FileLayer::ChunkRemote)` gate in `pull_all!` / `LibraryBroadcast.batch` with a capability — §14a keeps it a class check.
- Closing mirror staleness with a pull in a read path — §2 / §14a forbid it.
- Applying a page with one `Node.upsert_all` instead of per-row `find_or_initialize_by` + `save!`. That would cut about five statements per entry (find, uniqueness-validation SELECT, insert/update, manifest delete, manifest insert) and remove the Postgres race noted below. Rejected: it is a performance change, not a simplification. It bypasses Node's validations (`node.rb:6-8`), which today fail a malformed payload loudly. It needs a per-page dedupe, because a page routinely carries put + move for one node and Postgres refuses an ON CONFLICT DO UPDATE that touches a row twice. Steady-state pulls apply a handful of entries, and the first-sync cost is paid once.
- A shared `NETWORK_ERRORS` constant for the three identical rescue lists (`transport.rb:82-83`, `chunk_fetch.rb:33-34`, `57-58`) — line count. The robustness point is listed under defects.
- Filtering `pull_all!`'s fan-out to provisioned users (`where.not(sync_device_token: nil)`) — a performance gain for multi-user deployments only; `#perform`'s guard has to stay for the explicit-command path anyway.
- Deleting `full_resync` as dead code (unreachable today) — the protocol requires the fallback (§8.3), and the server already ships the prune. Fixing it is Opportunity 1.
- Merging `read`/`download`'s shared manifest + presign prelude — about four lines, and `read`'s MAX_BYTES check and content-token resolution differ.
- Tying `remote_sync_cursor` to the remote library's identity (reset on mint, or resync when cursor > head_seq) — a behaviour addition and a wire-semantics question shared with the Rust client (§14j); listed under defects.

## Defects noticed in-boundary (outside the simplification remit; each worth its own ticket)
- **Zero-byte files synced from a desktop mount are unreadable on chunk_remote (medium confidence).** FastCDC over an empty buffer yields no chunks (`../tinkerex-client/client/fs-provider/src/lib.rs:2110-2121`; the client treats empty manifests as a real state, `sync-engine/src/lib.rs:1300`), and the server accepts an empty manifest (`commit.rs:69-87`). `store_manifest` stores nothing for `[]` (`changelog_sync.rb:242`), and `read`/`download` raise NotFound "no manifest" (`chunk_remote.rb:151`, `191`), because "no rows" means both "not mirrored" and "empty". Web uploads are unaffected (`chunk_upload.js:36` always sends one entry). I did not trace the desktop push path end to end.
- **The cursor can sit AHEAD of the server and nothing notices.** `gapped?` only asks `cursor < oldest_seq` (`changelog_sync.rb:149-152`), and `head_seq` rides on every page but is read only on resync. A sync-server DB restore (`bin/restore-db sync` exists) or re-provisioning onto a fresh server leaves cursor > head_seq, so `since: cursor` silently skips the first (cursor − head) new entries.
- **Unmapped socket errors become 500s instead of 503s.** The three rescue lists omit `Errno::ENETUNREACH`, `Errno::EADDRNOTAVAIL`, `Errno::ECONNABORTED` and `Errno::EPIPE`. (net-http 0.9.1 converts ETIMEDOUT to `Net::OpenTimeout`, http.rb:1679-1680, so that one is covered.) `SystemCallError` is the robust spelling.
- **`remote_manifest_chunks` is append-only.** The only deletes are `store_manifest`'s per-version replace (`changelog_sync.rb:244`) and the user cascade (`user.rb:13`). Manifests of superseded or server-pruned versions accumulate forever (server version retention exists: `scheduler.rs:1-12`, off by default).
- **A Postgres-only concurrent-apply race.** `limits_concurrency` (`remote_changelog_pull_job.rb:44-45`) serialises job-vs-job only. A request's `refresh!` and the recurring pull can both insert the same new `node_id` → `RecordNotUnique` (unmapped → 500 in a request). SQLite (every live deployment) serialises page transactions in IMMEDIATE mode, so this is theoretical today.
- **Dead or vacuous tests.**
  - `LoopbackTransport`/`LoopbackFetch` are defined and unused (`mutation_contract_test.rb:26-69`, `upload_test.rb:12-67`; both now use `FileLayer.current`, at 105 and 100).
  - "pull_all! enqueues nothing on chunk" (`remote_changelog_pull_job_test.rb:102-104`) creates no users, so it passes on every leg, including chunk_remote where the gate is open.
  - "it applies REAL Sync::Changes output" (`changelog_sync_test.rb:214-233`) always skips.
- **Stale comments that contradict the code.**
  - `chunk_remote.rb:4-8` ("Not yet selectable… no chunk_remote arm") and `389-397` ("mkdir, move… are the next piece… left UNDEFINED").
  - `transport.rb:13` ("POST /v1/commits"; the route is /v1/commit).
  - `remote_changelog_pull_job.rb:96-108` (argues from `FileLayer::Chunk` in the gem).
- **`finalize_upload` does an unindexed lookup per upload.** `user.nodes.present.find_by(current_version_id:)` (`chunk_remote.rb:386`) has no `(user_id, current_version_id)` index (`schema.rb:504-509`), so every finalize scans the user's nodes. The by-version lookup itself is correct, because a conflict lands on a different node.
