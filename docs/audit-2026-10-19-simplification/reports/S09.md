## Opportunity 1: The Measure view's phase has two owners — give it one, the way the Gerber and 3D viewers already do
1. Verdict: recommend
2. Evidence:
   - The phase "drawn" lives in a CSS class, not in the controller. `draw()` adds `measure-view--ready` (app/javascript/controllers/measure_controller.js:235) and the stylesheet derives everything from it: the launch button stays visible and clickable until then (`.measure-launch { display: inline-flex }`, `.measure-actions { display: none }`, preview.css:234-235; `.measure-view--ready .measure-launch { display: none }`, :245-248).
   - There is no representation of "loading" at all: `load()` is unguarded (`const payload = await this.fetchPayload(); if (this.aborted || !payload) return; this.draw(payload)`, measure_controller.js:125-135), the poll runs up to 16,250 ms (`POLL_DELAYS_MS`, :47-49), and only the last sleep's timer is held (`this.pollTimer = setTimeout`, :178-180).
   - Per-draw state is ten separate fields with two partial reset paths. `draw()` writes `colors`/`unreadable`/`byObject` (:183-191), `nodeByShape` (:229), `allShapes` (:231), `svg` (:234), `panZoom` via `bindInteractions` (:237, :589-594 — which `setViewBox(home)`), and never resets `marked`/`nodeByShape`/`hovered`; `showPoster()` resets four of the ten (:141-147) and has no way to cancel a load in flight.
   - `connect()` (:95-118) builds a fresh empty `marked`/`nodeByShape` and does not reconcile with the element it is attached to.
   - Correctness is argued from the CSS gate in four places: print's guard ("in that window the button is display:none", :340-346), `clearMarks` ("NO `allShapes` GUARD ... Reset lives in .measure-actions, which is display: none without --ready", :742-746), `refreshPrintBar` (:814-837), and the test "printing before the geometry has loaded" ("neither can a user", test/system/measure_print_test.rb:3110-3117). `restingStatus()` dereferences `this.allShapes.length` unguarded (:695).
   - The same leak is documented as a hazard for the ✕ Image path only: "the button promises to print parts that are not marked, are not on screen, and are not even the objects the new payload drew" (measure_print_test.rb:2803-2808).
   - Precedent in this repo, same hazards, already fixed: gerber_controller.js keeps `this.generation` (:78), bumps it on dismissal and disconnect (:87, :198), shares one in-flight fetch (`this.pending ||= this.render()...`, :113) and adopts a result only if it still owns the stage (:115), and rests on connect — "AT REST, WHATEVER THE MARKUP SAYS. A Turbo Drive back-navigation restores the page from a snapshot taken WITH the stage open ... Resetting to the poster is the honest state" (:79-83). modelviewer_controller.js does the same (:37, :80, :92, :200, and :219 "cancel any in-flight load so it can't reopen the viewer after dismissal"). Commit ba5d6119 (2026-09-06) found the Gerber race in review, measured its symptom ("the button said hidden over a layer still drawn, with nothing in the console") and pinned it (test/system/gerber_test.rb:331-374). Measure — the controller svg_pan_zoom.js was extracted from — never got the same treatment.
   - Turbo Drive is on app-wide (app/javascript/application.js:2) and nothing exempts the file page from the snapshot cache (no `turbo-cache-control`/`turbo_exempts_page_from_cache` anywhere in app/views).
3. Current complexity or invalid states (all reachable from ordinary gestures; none recorded as reported):
   - Second Measure click during "Generating geometry…": two poll loops, two downloads of the payload (cards.dxf is 1,293 KB gzipped, measure-view.md:266-267/716) and two `draw()`s. The later draw replaces the SVG the user may already be working in, so the viewBox snaps back to home; contours marked on the first SVG stay in `marked`, so the bar reads "Print 2 parts" over an SVG with nothing highlighted, and re-clicking the same contour adds the new payload's object for it (that part prints twice, superimposed). `nodeByShape` keeps the superseded SVG's nodes.
   - ✕ Image after the first draw but before the second loop lands: the late `draw()` re-adds `--ready` and reopens the view the user dismissed — exactly the case modelviewer_controller.js:219 names.
   - Back to a file page where Measure was open: Turbo restores a clone with `--ready`, the drawn SVG, the `--marked` classes, the "Print 1 part" label and the readout, then connects a fresh controller with `allShapes`/`svg`/`panZoom`/`byObject` undefined. The cloned SVG has no listeners and no `__shape` expandos, so contours, pan and zoom are dead; Print/Download/Save silently no-op behind their `!shapes` guards while the label promises "Print 1 part"; Reset gets as far as `restingStatus()` and throws `TypeError` (`this.allShapes.length`); the unit toggle cannot rewrite the stale readout. Only ✕ Image recovers. That is the state the tests describe as unreachable.
4. Proposed representation and why it is simpler: one integer owns the stage, one method is the only way back to the poster, and `draw()` builds its own state. The DOM becomes derived from the controller instead of a second owner.
   ```js
   connect() { /* ...unit, readout as today */ this.generation = 0; this.pending = null; this.rest() }
   disconnect() { this.generation++; clearTimeout(this.pollTimer) }
   async load() {
     const gen = ++this.generation
     this.setStatus("Loading geometry…")
     try {
       this.pending ||= this.fetchPayload().finally(() => { this.pending = null })  // a 2nd click joins
       const payload = await this.pending
       if (gen !== this.generation || !payload) return                             // superseded: paint nothing
       this.draw(payload)
     } catch (e) { if (gen === this.generation) { console.warn(...); this.setStatus(...) } }
   }
   showPoster() { this.generation++; this.rest() }
   rest() { /* today's showPoster body: classes, stage, status, per-draw state, refreshPrintBar */ }
   draw(payload) { this.marked = new Set(); this.nodeByShape = new Map(); this.hovered = null; /* ...as today */ }
   ```
   Simpler because three states that today need four multi-paragraph "a CSS class hides that button" arguments become unrepresentable: a superseded load cannot paint, a restored snapshot cannot present a stage the controller does not own, and a redraw cannot inherit a selection. Optionally gather the per-draw fields into one `this.view` object so `rest()` is one assignment; and resolve hover through `nodeByShape.get(node.__shape)` so the second shape-to-element resolution (`__visible` + `styleNode`, :627-629, vs `top.__visible || top`, :229 — kept in agreement only by measure_print_test.rb:2632-2639) goes away.
5. Smallest credible implementation scope (one file, no interface change — same ERB targets/values, CSS, wire format; shape_svg/print_sheet/export_svg/svg_pan_zoom untouched):
   1. measure_controller.js: extract `showPoster`'s body into `rest()`; call it from `connect()` and `showPoster()`.
   2. measure_controller.js: `generation` + shared `pending` in `load()`; bump on `showPoster()`/`disconnect()`; report errors only for the owning generation.
   3. measure_controller.js: `draw()` creates `marked`/`nodeByShape`/`hovered` fresh. Optional: the `this.view` bundle and the single hover/selection index.
   4. Tests (below). Steps 1-3 without the bundle need no edits to existing probes.
6. Regression risks and migration concerns:
   - Data/API/backend legs: none. Client-only; the payload, its revisions and both `#geometry` endpoints are untouched, and the view reads the same JSON on share/s3/chunk_remote, so the three legs gain the same new system tests and keep identical run counts.
   - UI: after Back the user sees the poster instead of a dead open stage (the Gerber behaviour). A second Measure click joins the first fetch.
   - With a shared promise, a superseded load's rejection must not overwrite the owner's status (the `gen ===` check in `catch`).
   - Keep draw()'s documented ordering (no `await` between `replaceChildren` and `bindInteractions`; `populatePaper` after binding; `refreshPrintBar` last, :208-252).
   - If bundled into `this.view`: about seven probe sites in measure_print_test.rb change (2687, 2692-2693, 2819, 2839, 3024-3025, 3145), plus the comments that name the fields. Either way, the "display:none so unreachable" prose (:340-346, :742-746, :814-837; measure_print_test.rb:3110-3117) should be rewritten in the same change to argue from the controller's state.

## Considered and rejected
- **One curve-descriptor carrier for the three traversals.** Today they differ: `Lbrn2.each_geometry` yields seven positional values, with `ellipse` and `segments` as two mutually exclusive nullable slots (lbrn2.rb:253-268); `SvgGeometry.walk` yields `curve` + `segments` (svg_geometry.rb:98-110, 179-181); `Dxf.each_geometry` already yields a tagged `{type: :circle|:arc|:path}` hash (dxf.rb:803-806). Not material:
  - the shared typed model already exists exactly where sharing happens, `Collector#add`'s keyword interface (geometry.rb:245);
  - each traversal's yield is private to its own format's two consumers;
  - the "at most one non-nil" pair is guaranteed by separate `case` arms, with no recorded defect;
  - unifying rewrites five producer/consumer sites, including two thumbnail paths, for uniformity alone ("moving branching behind a type"). Only DXF has byte digests (dxf_geometry_test.rb:218-240), so the LBRN/SVG legs would be guarded by value assertions only.
- **One helper for the client-space map and the segment-pair map.** Five 3-line copies exist: lbrn2.rb:432-436, dxf.rb:326-331, svg_geometry.rb:122-126 and 188-192, dxf_geometry.rb:121-125. Each is pinned by a per-leg "control points ride the same transform" test, so consolidating is line-count only. Unifying the two matrix conventions (Lbrn2/SvgGeometry `x' = a·x + c·y + e` vs Dxf `x' = a·x + b·y + e`) would touch the INSERT code whose bit-identity licenses the unbumped digests.
- **One transform-survival rule for descriptors** (Lbrn2 `axis_aligned?`, `SvgGeometry.ellipse_curve_for`'s gate, `Dxf.transform_curve`'s similarity test). The forms differ: DXF `:circle` carries one `r`, LightBurn/SVG ellipses carry rx/ry. One rule would change DXF output (an inserted circle under a non-uniform scale would gain an `e`), forcing a DxfGeometry bump and a re-measure of every `.dxf`. measure-view.md:560-593 records the per-leg arms and warns against "fixing" them by analogy.
- **A geometry-builder table replacing the per-renderer `kind == "geometry"` arms, `REVISIONED_BY` and `MEASURABLE_EXTS`.** The duplication is real, but the dispatch it would replace lives in Registry/Enqueue/GeneratePreviewJob (S08) and FilePreview (S10). See the cross-subsystem notes.
- **Keeping the payload across ✕ Image → Measure,** as the Gerber controller keeps its render (gerber_controller.js:100-116). It would save a re-download of up to 1,293 KB gzipped per round trip. But holding a client-side payload after the file changed cuts against measure-view.md:286-291 ("an older build's payload is wrong, not merely old"). That is a product decision, not a simplification, and it is deliberately not part of Opportunity 1.
- **Splitting dxf.rb (1,499 lines) into lexer/blocks/splines/thumbnail files.** This is organisational only. The parser is cohesive and its length is mostly recorded argument.
- **Computing `Dxf.layer_records` once.** Today it walks every pair twice per render (`layer_colors` + `layers_off`, dxf.rb:1087-1118, reached from dxf_geometry.rb:49 and dxf.rb:125). The cost is small next to `tokenize` and the measured 1.54 s worst render, so it is not material.
- **Sharing one SVG emitter between the Lbrn2 and Dxf thumbnails** (`wrap_svg`, `BBox`, formatters). The split is deliberate ("kept local to avoid coupling", dxf.rb:1468-1469), and any byte change forces `THUMBNAIL_REVISION` bumps that re-render about 1,400 thumbnails.
- **A positional DXF entity record so LWPOLYLINE bulges could draw.** That would retire the `LWPOLYLINE(bulge)` tally, but zero real bulges are on LWPOLYLINE (measure-view.md:136-141). Hypothetical.
- **Three spellings of the LightBurn "attribute or child Value or child text" read.** `Lbrn2.setting` and `cut_colors` read child-first (lbrn2.rb:345-347, 531); `LbrnMetadata.val` and `MageMetadata.val` read attribute-first with `presence` (lbrn_metadata.rb:95-97, mage_metadata.rb:73-75). So the panel swatch and the Measure colour read one `<color>` with different precedence. No corpus file carries `<color>` at all (lbrn2.rb:520-524), so the divergence is latent and not material.
- **Defects noticed in passing.** These are in the boundary but are not simplifications; route them separately.
  - The payload's `i` means "an upright, base64 PNG the thumbnail can place" on the LightBurn leg (`bitmap_image`, lbrn2.rb:400, 499-511 → `image: !image.nil?`, lbrn_geometry.rb:86) but "an `<image>` element" on the SVG leg (svg_geometry.rb:165). So a rotated or non-PNG LightBurn Bitmap reaches Measure, print and export as a solid layer-coloured cut contour instead of the dashed photo placeholder (measure_controller.js:531-540, print_sheet.js:222-224, export_svg.js:58-60). Only the upright-PNG case is pinned (lbrn_geometry_test.rb:75-90). The fix needs `LbrnGeometry::FORMAT_REVISION` +1.
  - The paper preference reads and writes localStorage unguarded (measure_controller.js:279, 297); the unit preference is guarded (:304-311, :316-321). In blocked storage, `populatePaper` throws inside `draw()` after the resting line is written, so `load()`'s catch (:131-134) replaces it with the DOMException text, and `paperChanged` throws uncaught.
  - Comment nit: geometry_test.rb:94-95 says DXF bumped "its OWN term again, 3 -> 4". The FORMAT term went 2 → 3 (dxf_geometry.rb:21-32; measure-view.md:46); 4 is the total.

## Cross-subsystem notes
- S08/S10/V1: `Registry.render` passes `kind:` only to renderers whose `render` declares it (registry.rb:162-168). A renderer that accepts and ignores it (`Stl.render`, stl.rb:52-54) or does not declare it (pdf, image_thumb, three_mf, gerber) builds a thumbnail under `kind: "geometry"`. Two doors reach this: `FilesController#geometry` enqueues for any present node with no `MEASURABLE_EXTS` check (files_controller.rb:445-485), and the V1 previews endpoint takes `kind` from the client (previews_controller.rb:46, 107). A geometry row can then hold a PNG and be served as `status: ready` to a JSON consumer. The public door gates on `@kind == :measure` (public/files_controller.rb:74). The geometry-capable set is spelled in about six places: `MEASURABLE_EXTS` (file_preview.rb:29); the `render`/`payload_revision` arms in lbrn2.rb:171-185, mage.rb:51-65, dxf.rb:40-71 and svg.rb:22-43; and `Geometry::REVISIONED_BY` (geometry.rb:226). GeometryTest holds them together. One ext → builder table read by the job would let an unsupported kind fail closed as `unsupported`.
- docs/adding-a-preview-format.md:30-34 (step 5) names `REVISIONED_BY` and the revision constants but not `MEASURABLE_EXTS`, the `render(kind:)`/`payload_revision(kind)` arms, `available_for?`, or GeometryTest's `MEASURABLE_FIXTURES`/`GEOMETRY_REVISIONS`. The tests catch each omission; the walkthrough does not list them.
- S22: modelviewer_controller.js:35-40 (lazy mode) does not rest the element on a Turbo snapshot restore, unlike gerber_controller.js:79-83. It is the same hazard as Opportunity 1's third path.
