## Opportunity 1: One parameter-schema representation per sidecar — `param_groups` only. This finishes F-62, whose out-of-repo gate is now met, and does the same for openscad.
1. Verdict: recommend

2. Evidence
   - The boxes sidecar's `/generators` emits every generator's schema twice.
     - `sidecar/boxes/app.py:383-392` writes `"param_groups": grps` and also `"params": [p for g in grps if not g["advanced"] for p in g["params"]]` (`:391`).
     - The comment at `:388-390` says: "Back-compat: a previously-deployed app read a flat `params` … Safe to drop once every app consumes `param_groups`."
   - `sidecar/boxes/tests/test_api.py:316-370` (F-62) pins the flat key instead of deleting it. The reason it gives (`:326-342`) is: "SO, BEFORE DELETING THE KEY: grep chaim354/tinkerex-addons for `.params` on a generator object -- AND any pinned older build still being served".
     - Its own measurement (`:320-321`) is that the flat list omits "2403 of the 5082 params … 47%". The prior audit's text is "A consumer binding to `params` renders a form missing all edge/part settings with no error anywhere" (docs/AUDIT-2026-08-19.md:1369-1377, F-62: "ACCEPTED, gated on an out-of-repo check"). The fix log at docs/FIX-LOG-2026-08-19.md:1542 records it as "A PIN, NOT A DELETION".
   - The openscad sidecar has the same duplication.
     - `sidecar/openscad/schema.py:21-26`: `normalize` returns `{"params": params, "param_groups": _group(params)}`. Each param also carries `"group"` (`:37`), which is a third statement of which group it belongs to.
     - `app.py:84-88` merges both lists into every catalog entry (`item.update(_schema_for(...))`), and `/params` returns both (`:120-128`). Every param therefore crosses the wire twice.
     - The sidecar itself reads only the grouped form: `_coerced` uses `_schema_for(scad)["param_groups"]` (`app.py:190`) and coerce.py flattens `param_groups` again (`coerce.py:69`).
   - The same key means two different things in the two sidecars. In boxes, `params` is the lossy non-advanced subset. In openscad, it is every param. On the request side, `params` means the submitted VALUES in both (`/generate {generator, params}`, `/render {scad, params}`).
   - `schema.py:1-5` still claims it is "deliberately the SAME shape BoxesClient::Generator uses". BoxesClient was deleted on 2026-08-03 (6095b871), and the two shapes no longer match.
   - The gate F-62 named is now met. Evidence:
     - At the bundle repo's tip (d3ab6fd), each bundle reads only `param_groups`: `openscad/openscad.js:175,191`, `openscad/editor.js:158`, `boxes/editor.js:186`, and both `fields.js` read `group.params`.
     - A `git grep` over every commit in tinkerex-addons that touches `addons/` finds no read of a top-level `.params`. The only hits are `state.data.params` (a saved item's values) and `group.params`. The first boxes bundle commit (f178b70, 2026-08-03) already read `param_groups`.
     - `bin/rollback` only re-tags images built from those commits, so no older bundle build a rollback could restore reads the flat key either.
     - On the Rails side, even the deleted BoxesClient read only `param_groups`: `6095b871^:app/services/boxes_client.rb:12,28` slices `:key, :title, :group, :param_groups`.
     - The flat key's last reader predates 4105ddea (2026-07-21). Self-host compose arrived on 2026-10-13. The Rails suites' fake already serves the post-deletion shape: every `"params" =>` in `test/support/fake_boxes_sidecar.rb:67-111` is nested inside a group.

3. Current complexity or invalid states
   - Each sidecar's schema has two representations that nothing keeps consistent except tests. For boxes, one of them is lossy by design.
   - A consumer that binds to the flat key gets a form missing half the knobs, with no error. That includes any future bundle whose author reads either sidecar's README or a sample response.
   - The key also means different things across the two sidecars, so code ported from one bundle to the other is silently wrong.
   - Today's cost:
     - About 60 lines of boxes test that exist only to pin a key with no reader.
     - Openscad tests that assert on the redundant list rather than the one the code uses (`test_schema.py:27-28,35`, `test_api.py:98,106`, `test_catalog.py:93`, `test_coerce.py:296`).
     - A doubled payload on every gallery load.
     - Docstrings (`schema.py:1-5`, `app.py:60`) describing a Rails consumer that no longer exists.

4. Proposed representation and why it is simpler
   ```python
   # sidecar/openscad/schema.py
   def normalize(dump):
       raw = dump.get("parameters") or []          # TRAP 1 unchanged
       return {"param_groups": _group([_param(p) for p in raw])}
   # optional: _group pops each param's "group" key, so membership is stated once (by the enclosing group)

   # sidecar/boxes/app.py, /generators
   out.append({"key": key, "title": ..., "group": ..., "param_groups": grps})
   ```
   - There is one schema shape per sidecar, and it is the one both bundles and the sidecar's own coercion already read.
   - There is nothing to keep in step, and no lossy view a consumer can bind to by mistake.
   - At the top level, `params` then means only "submitted values" on the wire.

5. Smallest credible implementation scope
   1. `sidecar/boxes/app.py:388-391`: delete the comment and the key.
   2. `sidecar/boxes/tests/test_api.py:316-370`: replace the F-62 pin with an absence assertion (`"params" not in g` for every entry). This is the follow-up F-62 itself named ("Add a test that the key is absent so it cannot be reintroduced").
   3. `sidecar/openscad/schema.py`: change `normalize` and its docstring (`:1-5`). Optionally pop `group` in `_group`.
   4. `sidecar/openscad/app.py:60` and the `/params` docstring: wording only. `_coerced` is unchanged.
   5. openscad tests:
      - `test_schema.py` (`by_name` flattens `param_groups`; the zero-param case asserts `param_groups == []`).
      - `test_api.py:95-107`.
      - `test_catalog.py:93` (count across groups).
      - `test_coerce.py:296` (the fixture stub returns only `param_groups`).
   6. Publish both images with `bin/publish-sidecar boxes` and `bin/publish-sidecar openscad`. No Rails deploy is needed.
   7. Out of repo, comments only: tinkerex-addons `openscad/sidecar.js:23-26,38-40` and `openscad/fields.js:11-15` describe `params`/`group`. No bundle code changes.

6. Regression risks and migration concerns
   - The only plausible break is an unknown, out-of-tree addon that declares `services: ["boxes"]` or `["openscad"]` and reads the flat key. It would get an empty form rather than an error. No first-party bundle ever read the key (see the history scan above), and the sidecars' JSON shapes are not part of the documented addon API (docs/addon-api-v1.md documents the proxy, not sidecar endpoints).
   - Deploy order does not matter, because every current consumer already reads only `param_groups`.
   - No Rails code, data, or backend leg is touched: share, s3 and chunk_remote are unaffected, and FakeBoxesSidecar already emits this shape.
   - The openscad render cache keys on the coerced values, not the schema, so it stays valid.
   - Re-run the tinkerex-addons grep at implementation time, because the tip may have moved.

   - Already pinning the behaviour that matters:
     - boxes: `test_generators_shape`, `test_every_generator_renders_with_its_own_advertised_defaults` and the `choice_labels` sweeps, which all read `param_groups`.
     - openscad: test_schema's type, trap and grouping tests (re-pointed at the groups), and test_coerce, which already reads `param_groups`.

   EXTERNAL_REFERENCES = [ "include <", "use <", "import(", "surface(" ].freeze

       entries.each do |entry|

     - `test_every_entry_exposes_parameters`.

## Considered and rejected
- **Folding `Tinkerex::Sidecars`' touchpoint tables into one record list.** The tables are `FILES`, `MARKERS` (`:39-46`), `snippets` (`:80-112`), the 9-tuple `problems_for` (`:132-154`), the generator's prose anchors and inserts (`sidecar_generator.rb:20-22, 42-48, 78-80`), and `strays`' scan set (`:162-177`). This is the brief's question 2. The honest answer is "several lists kept in step", but every disagreement between them fails loudly:
  - `snippets.fetch` raises.
  - The generator's own `generate → problems == []` test and its `destroy → byte-identical` test pin agreement as behaviour (`sidecar_generator_test.rb:40-67`).
  - `sidecars_test.rb:366-375` pins each YAML snippet's parsed values.
  - `problems_for` already reads as one 9-row table.
  - A YAML insert (before a marker) and a prose insert (after a regex) are different operations, so one record type would need an anchor union, which means moving branching behind a type.
  - The module landed on 2026-10-18 by design (spec §3-4), and no invalid state is reachable.
- **A `kind` discriminator on `Problem`.** Today the kind is encoded in the `file` string ("(stray)", "sidecar/<name>/" or a `FILES` path) and read at five sites: `sidecars.rb:24,28`, `sidecar_generator.rb:116`, `sidecars.rake:14`, `sidecar_hygiene_test.rb:11`. A discriminator would be clearer, but every constructor sits in one file and no contradictory combination is reachable. The change is cosmetic.
- **One shared HTTP contract module for sidecars (error shape, `/up`, JSON body parsing).**
  - The three error shapes really differ: boxes sends `{"error"}` only (`app.py:352,368-373`); openscad adds `code: "invalid_params"` only for coercion (`app.py:151`); the template always sends `code` (`app.py.tt:31-32`).
  - `/up` also differs: Flask's default `text/html` in both sidecars, `text/plain` in the template.
  - But the only contract any consumer reads is `{"error": prose}` on a non-2xx (both bundles' `sidecarMessage`; the SDK's raw-text `ServiceError`).
  - Each sidecar is a separate GPL image with its own build context (boxes GPL-3.0, openscad GPL-2.0-only), so a shared module would be copied into each and would need a licence compatible with both — for 3-5 lines per sidecar.
  - The capability script (`assert-capabilities.sh`) is specific to OpenSCAD's compile-time options (Manifold, lib3mf, `--export-format=param`). boxes.py is pure Python, so there is nothing to share, and the template rightly scaffolds none.
- **Making the proxy's `PROXIED_INLINE_TYPES` and the sidecars' mimetypes one declaration** (brief question 4). The allowlist is a security policy, not a mirror of what sidecars emit. Unlisted types degrade to `octet-stream` + `attachment` by design (`addons_controller.rb:1271-1284`), so drift cannot break a sidecar, and Rails may never import sidecar code (§9).
- **"catalog.json duplicates the .scad"** (brief question 3). It does not.
  - Parameter type, bounds and defaults are derived at runtime from the `.scad` itself (`render.params_for` → `schema.normalize`). schema.py and coerce.py share that one normalized param dict, with "choices beats type" applied in both, as intended.
  - catalog.json holds only the metadata the byte-for-byte upstream files cannot carry (NOTICE "MODIFICATIONS: None").
  - `file` always equals `key + ".scad"`, which is trivially derivable.
  - The licence, attribution and ref appear again in NOTICE by compliance design, and the hygiene guards check both directions.
- **Unifying `choice_labels`.** It is a `{choice: label}` map in boxes (`app.py:175-196`) and a parallel list in openscad (`schema.py:48-49`). Each bundle has its own `fields.js` reading its own sidecar's shape, so unifying would be a coordinated two-repo change for consistency only.
- **The `vector_names` arm and the list/tuple arm of `render.param_set_json`/`render.render`** (`render.py:92-116,124`). They are a second vector encoder that no production caller can reach: `/render` never passes `vector_names`, and `coerce._vector` already brackets, including the one-element case this arm cannot handle. That is about 15 lines whose comment argues for keeping them for direct callers. Line count only.
- **The render-deadline chain.**
  - The pieces: `render.py` `TIMEOUT_S` (env `OPENSCAD_TIMEOUT`, set nowhere, default 60) must stay below gunicorn's `--timeout 120` (`Dockerfile:128-131`) and at or below the manifest's `service_timeouts: 90` (tinkerex-addons `manifests.json:58-60`). `params_for` hard-codes 30 (`render.py:193`).
  - Raising the env knob silently breaks the "clean 422, not a worker crash" rule. The fix is one line (drop the knob, or derive gunicorn's value), not a structural change.
- **F-76 (2026-08-19 audit, ACCEPTED).** The boxes.py commit is pinned twice: `sidecar/boxes/Dockerfile:20` (`ARG BOXES_REF`) and `requirements.txt:5`. `README.md:20` and `requirements.txt:3-4` tell a forker to change only the latter.
  - It is still unlanded at HEAD (verified: no FIX-LOG row, both pins present).
  - Not re-raised as a new finding, to avoid a duplicate; the coordinator may carry it forward. Its proposal (derive the ref from requirements.txt in the RUN) still applies verbatim.
- **Memoizing boxes' `/generators`** (about 70 ms per call per its own docstring; the catalogue is immutable) and **openscad's per-entry re-read of `catalog.json`** (`_source_path` inside the `/generators` loop). Micro-performance only.
- **bin/build-sidecar re-spelling the name regex and image convention in bash** (`:56,68`). The convention is pinned by `deploy_hygiene_test.rb:451-452`, and bin/publish-sidecar deliberately asks `--revision` before a Rails boot. Port 8000 appears both in `Sidecars::PORT` and in each CMD; changing it is hypothetical.
