## Opportunity 1: Define the icon rail once, as a container query on `.rail`, not as a body-class copy plus an unscoped viewport copy
1. Verdict: recommend
2. Evidence
   - `app/assets/stylesheets/shell.css:71-82` is the collapsed copy, with every selector prefixed `.rail--collapsed`. That body class is emitted only inside the shell (`shell_helper.rb:108-113`).
   - `shell.css:160-168` is the viewport copy (`@media (max-width: 1099px)`). It holds the same rules without the prefix: `.brand { justify-content: center; padding: 4px 0; }` (163) and `.brand-name, .rail-label, .rail-user, .rail-btn span { display: none; }` (164).
   - Diffed with the prefix stripped, the two blocks are identical except for two collapsed-only lines that do nothing. `.rail--collapsed .rail-foot form button` (77) adds nothing because that button already carries `.rail-btn` (`_rail.html.erb:110`). `.rail { padding-inline: 8px }` (72 and 162) restates line 9's `padding: 14px 8px`.
   - The two copies have been edited together. Four commits touch both: 9bcb1839 (09-03), bfa31f4b and a8389120 (10-08), bcd55562 (10-09). The browser suite needs a second test only because a second copy exists. `test/system/shell_test.rb:77-79` says the test exists because "shell.css carries a SECOND copy of the family-lit rules inside that media query — which the collapsed-cookie test above cannot reach" (tests at :47 and :80).
   - The unprefixed copy also matches every `.brand` outside the rail. Two surfaces undo it:
     - `shell.css:22-29`: `.public-header .brand-name { display: inline; }`, with the comment "THE `.brand-name` OVERRIDE IS NOT TIDINESS".
     - `pages/landing.css:17-21`: "the ≤1099px rail rules hide `.brand-name` and centre `.brand`, so this restores both".
   - The third surface, the auth card, has no override. It renders `<div class="brand">…<span class="brand-name">Tinkerex</span>` in `users/sessions/new.html.erb:2` and five sibling Devise views. It is `/` on every self-hosted box (`web/landing_test.rb:38-44`), and no rule anywhere names `.auth-card .brand-name` (grep). Below 1100px its wordmark is therefore `display: none` and the mark sits centred alone.
   - `shell_helper.rb:99-101` records fixing exactly this for the cookie path: "a user who collapsed the rail and signed out landed on a sign-in card with its wordmark hidden (found in review, 2026-09-04)". The guard for that fix (`web/shell_layout_test.rb:93-102`) checks only the body class. `auth_pages_test.rb:130` and `landing_test.rb:42` check the wordmark's markup, which a CSS hide cannot fail.
3. Current complexity or invalid states
   - One UI state, "the rail is icons only", has two triggers (the cookie and the viewport). Each trigger has its own hand-synced rule copy, and the two copies are scoped differently.
   - Any edit to the icon rail has to be made twice, and each behaviour needs two browser tests.
   - The viewport copy styles elements outside the rail. Every surface that reuses `.brand` must remember a compensating override. One surface forgot: the self-host front door's sign-in card loses its name on phones and tablets.
4. Proposed representation and why it is simpler

   The rail measures its own width. The two triggers keep doing the one thing they already do, which is set the grid track width.

   ```css
   @layer shell {
     .rail { /* …existing… */ container: rail / inline-size; }   /* width = the grid track (216px / 56px) */
     /* THE ICON RAIL, ONCE: collapsed by the cookie or narrowed below 1100px. Both only set the track;
        this asks the rail's own width, so nothing outside the rail can match it. */
     @container rail (max-width: 120px) {
       .brand { justify-content: center; padding: 4px 0; }
       .brand-name, .rail-label, .rail-user, .rail-btn span,
       .rail-group-head, .rail-project, .rail-pin { display: none; }
       .rail-link, .rail-btn { justify-content: center; padding-inline: 0; }
       .rail-family-lit { color: var(--fg); background: var(--surface); box-shadow: inset 0 0 0 1px var(--line); }
       .rail-family-lit::before { content: ""; position: absolute; left: -8px; top: 8px; bottom: 8px; width: 3px; border-radius: 0 2px 2px 0; background: var(--fg); }
     }
     body.app-shell.rail--collapsed { grid-template-columns: var(--rail-collapsed-width) minmax(0, 1fr); }
     @media (max-width: 1099px) { body.app-shell { grid-template-columns: var(--rail-collapsed-width) minmax(0, 1fr); } /* top-bar rules unchanged */ }
   }
   ```

   - The content-box width is 39px collapsed (56 − 16 padding − 1 border) and 199px expanded, so any threshold between those two works.
   - The scoping is built in: a container query matches only descendants of a `rail` container. The auth card, `.public-header` and `.landing-nav` therefore cannot match, and their overrides can be deleted.
   - The result is one rule block in place of two, with no leaking selector and no overrides.
5. Smallest credible implementation scope (in order)
   1. `shell.css`: add `container` to `.rail`; add the one `@container` block; reduce 71-82 to the grid rule; delete 162-168; delete line 29 and rewrite its comment (17-25).
   2. `pages/landing.css:17-21`: drop `justify-content: flex-start` and `.landing-nav .brand-name` (`padding: 0` can stay as a landing choice).
   3. Comments only: `shell_helper.rb:99-102` (the code is unchanged, since `rail--collapsed` still drives the grid rule) and `shell_test.rb:77-79`.
   4. `docs/invariants/design-system.md` rule 8: record that the icon rail is one container query and that the rail's width must stay the grid track's.
6. Regression risks and migration concerns
   - `container-type: inline-size` applies inline-size, layout and style containment to `.rail`.
     - The rail's width can no longer come from its content. That is fine while the track is a fixed length; a future `auto` or content-sized track would collapse the rail, so record it in rule 8.
     - `.rail` becomes the containing block for any `position: fixed` descendant. There are none today: the rail holds links, two buttons and a `button_to` form, and the lit marker is absolutely positioned inside `.rail-link`. `overflow: hidden auto` already clips absolutely positioned children.
   - Browser floor: size container queries need Chrome 105, Safari 16 and Firefox 110. That is inside `allow_browser :modern` (Chrome 120 / Safari 17.2 / Firefox 121 in actionpack 8.1.3.1), and the rail renders only behind ApplicationController.
   - CSS only: no data, API or backend-leg impact, and it is identical on share, s3 and chunk_remote.
   - Visible changes:
     - The auth card keeps its wordmark below 1100px. That is the intended state per `shell_helper.rb:99-101` and `auth_pages_test.rb:129`.
     - The public header's brand keeps its 8px padding at narrow widths.
7. Existing and additional validation required
   - Tests that already pin the behaviour:
     - `system/shell_test.rb` :23 (collapse survives navigation), :47 (collapsed family-lit), :80 (narrow family-lit), :107 (Sign out is a one-line icon in the narrow rail), and the 375px sweep.
     - `web/shell_layout_test.rb` :93, :127, :217.
     - `system/landing_test.rb` (375px overflow) and `system/phone_topbar_test.rb`.
     - `css_hygiene_test.rb`. Its parser records `@container` as an at-rule inside `@layer shell`, so both the layered check and `layer_of` still pass.
   - New test (a), "below 1100px the sign-in card and the visitor's header keep their wordmark":
     - Set the viewport through CDP to 900px and to 375px, signed out.
     - Check that the computed `display` of `.auth-card .brand-name` is not `none`. Do the same for `.public-header .brand-name` on a public page and `.landing-nav .brand-name` with demo mode on.
     - This test is red on today's tree; that is the defect.
     - Mutation: put back the unprefixed `.brand-name { display: none }` in the ≤1099px media block. The test goes red.
   - New test (b), "the two triggers draw one rail":
     - Compare a fingerprint of computed styles under two states: the collapsed cookie at 1440px, and the expanded cookie at 900px.
     - Fingerprint fields: `.rail-label` display, `.brand` justify-content, `.rail-link` padding-inline, and the family-lit `::before` content.
     - Assert the two fingerprints are equal.
     - Mutation 1: drop `.rail-label` from the container block. Both arms go red.
     - Mutation 2: delete the `body.app-shell.rail--collapsed` grid rule. Only the cookie arm goes red.
8. Confidence: medium-high
   - Both rule blocks were diffed, and the grep shows no `.brand-name` rule for the auth card.
   - The sign-in-card symptom is inferred from the cascade, not observed in a browser (this review was read-only). Containment side effects are the one thing the browser tier must confirm.

## Considered and rejected
- **Threading of per-page shell state.**
  - Each kind of state uses a mechanism that fits how long it lives:
    - theme and rail live in cookies rendered at first byte (`shell_helper.rb:68-73`);
    - the folder and the Upload accent are controller ivars exposed through `helper_method` (`folder_destination.rb:20-38`);
    - the lit link is derived from `controller_path` plus `@crumbs`/`@project` (`shell_helper.rb:157-180`);
    - title, crumbs, container class and head go through `content_for`;
    - an unreachable library is flagged on `Current.library_unreachable`.
  - Each kind has one reader. A ShellState object would only move the branching behind a type.
  - The softest coupling is the helper reading `@crumbs`/`@project` implicitly. It is pinned by `shell_layout_test.rb:77-90,187-212` and `workspace_test.rb:90`.
- **FolderDestination's two flags** (`@upload_primary` and `Destination#primary`). Rule 13 records why "ask" cannot be a Destination with a nil `node_id`: a nil `node_id` means the library root. This also belongs to S06.
- **Recent vs Files/Projects.**
  - `HomeController#index` is four bounded one-line queries over existing scopes.
  - `where.not(status: "archived")` is spelled out at `shell_helper.rb:127`, `files_controller.rb:1172` and `inventory_items_controller.rb:57`. Recent deliberately also excludes `done` (`home_controller.rb:27-29`). A `Maker::Project` scope would be a one-line nicety.
  - The Recent tile duplicates the hub's "library tile" and has drifted from it (see cross-notes). That fix lives in S15's views.
- **Landing tiles vs the rake task.** They already share one model. `Tinkerex::Landing` (TILES, SIZE, `Tile#asset`) is read by the view (`landings/show.html.erb:51-56`), the rake task (`landing.rake:7-8`) and the tests.
  - The four crops are listed twice, in `capture_crops.rb:20-53` and `landings/show.html.erb:87-118` (both 1120×700).
  - The script runs outside Rails, and `lib/tinkerex/landing.rb` reads `Rails.root` at load (34-35). Sharing would cost a Rails boot to read four names.
- **Stylesheet drift.**
  - Every page sheet is linked on every page (`application.html.erb:20-22`). Nothing loads per page except the sheets grid's vendor CSS (`projects/sheets/show.html.erb:38`).
  - The sheet list exists three times: the layout, `OURS` (`css_hygiene_test.rb:26-29`) and the link-order list (`:117`). All six additions so far were made in lockstep.
  - The real hole: a page sheet that is linked but missing from `OURS` escapes both the layered check and the component check.
  - Deriving `OURS` from `Dir.glob("pages/*.css")` would follow the file's own "derived, not written down" rule (`:137`). That is a guard improvement, not a simplification of the app.
- **Dark tokens written twice.** `application.css:78-103` and `104-131` hold 23 identical declarations (diffed), and `vendor-overrides.css:47-58` paints the CodeMirror light theme twice.
  - `light-dark()` would collapse the token blocks, but it needs Chrome 123 / Safari 17.5, while `allow_browser :modern` (`application_controller.rb:3`) admits Chrome 120 / Safari 17.2. In that gap every `var(--bg)` would fail at computed-value time.
  - Rejected unless the browser floor is raised. A parity assertion would be the cheap guard instead.
- **`hello_controller.js`** is dead Rails scaffold: no view names it, yet `pin_all_from` (`config/importmap.rb:7`) preloads it on every page. `stimulus_hygiene_test.rb:24-27` cites it as the example of an unreferenced controller. Deleting it is housekeeping, not a representation change. The test's `:141` uses the name only as synthetic input.
- **PWA files.** `app/views/pwa/` is unrouted: there is no `rails/pwa` route and no `<link rel="manifest">`.
  - Yet design-system.md rule 4 (33-36) counts the manifest among the four places the default theme must agree.
  - Its `theme_color` (#fcfbf8) also differs from the meta theme-color (#f4f2ed, `shell_helper.rb:229`).
  - Delete the files (rule 4 then drops to three places) or route them. Housekeeping.
- **Theme label lags across the two theme controllers.** Changing the theme on Settings leaves the rail's label stale until the next render (`theme_controller.js:9-11`, `settings_theme_test.rb:29-34`). It is documented, it fixes itself on any navigation, and a three-line window event would remove it. Below the bar.
- **`theme-color` for `system` is always Paper** (`shell_helper.rb:227-229`, `theme_controller.js:15`), so on a dark OS the browser chrome stays light. Two media-qualified `<meta name="theme-color">` tags would fix it. This is a small defect, not a simplification.
- **Page-title suffixing.** About 38 views write " — Tinkerex" (Suppliers, Shelves and Locations use a hyphen), and `page_title_text` strips it again with a regex (`shell_helper.rb:223-225`). A `page_title` helper would touch views across many rows for no behaviour change. Stylistic.
- **`shell_signed_in?`/`public_shell?` as a three-value enum.** Both live in one method together with the load-bearing ordering argument (`shell_helper.rb:75-97`). An enum would only move the branching behind a type.
- **SettingsController#show's five COUNTs**: bounded, on one page.
- **The `unless: :devise_controller?` belt** (`application_controller.rb:9-38`): its comment records why it stays.
- **`app/assets/images/landing/library.jpg`**: an untracked leftover in the working tree of a file that ff8e90fc deleted. It is not in the repo.
