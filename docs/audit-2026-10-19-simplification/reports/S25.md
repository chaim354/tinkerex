2. Evidence

4. Proposed representation and why it is simpler

   # bin/secrets-preflight (resolves each name through the real Kamal::Secrets) and
   # test/deploy_hygiene_test.rb (static, vault-free). Reads config only, never a secret value.
   module Tinkerex
     module DeploySecrets
       DESTINATIONS = [ nil, "s3", "share", "ovh" ].freeze   # nil = base (`kamal deploy`, no -d)
       def self.label(destination) = destination || "base"
       def self.at(node, *path) = path.reduce(node) { |v, k| v.is_a?(Hash) ? v[k] : nil }
       def self.names(raw) = …   # the nine arms, moved verbatim with their kamal file:line comments
       def self.required(destination, config_file:)
         require "kamal"   # lazily: production eager-loads lib/ and never calls this
         keys = names(Kamal::Configuration.create_from(config_file:, destination:).raw_config)
         raise "no secret keys resolved for #{label(destination)} — raw_config shape changed?" if keys.empty?
         keys
       end
     end
   end

     preflight already does, so kamal's file selection is reflected rather than re-implemented.
   - Why it is simpler: one algorithm and one list. "Widen both" stops being a rule anyone has to remember. The
     existing oracle starts guarding the code that actually runs before a deploy. Nothing new is invented: this is the
     shape Tinkerex::Sidecars and ImportmapAudit already use.

     it lands. This needs the dead deploy.r2.example.yml deleted or excluded. The pin at test:879 stays as the explicit

4. Proposed representation and why it is simpler (bash 3.2-safe, because restore-db would run `--describe` on the Mac)
   ```bash
   # THE ONE DESTINATION TABLE: name, the container whose image does the work, the volume holding its
   # databases. The accepted arguments, the ping lookup and bin/restore-db all read it.
   DEST_TABLE='
   chunk  ^tinkerex-web-[0-9a-f]  tinkerex_storage
   share  ^tinkerex-web-share-    tinkerex_storage_share
   s3     ^tinkerex-web-s3-       tinkerex_storage_s3
   sync   ^tinkerex-sync$         tinkerex_sync_storage
   '   # sync stays ANCHORED: the comment at :196-204 moves beside this row, unchanged
   dest_row()   { printf '%s\n' "$DEST_TABLE" | awk -v d="$1" '$1 == d { print $2, $3; f = 1 } END { exit !f }'; }
   dest_names() { printf '%s\n' "$DEST_TABLE" | awk 'NF { print $1 }'; }

   # Argument loop: `--list` and `--describe NAME` print and exit, before any ping, like every other
   # argument guard. A bare word is accepted only if dest_row knows it.

   # Ping: no shell variables are assigned, so there is no whitelist to keep in step. ping.env is still
   # PARSED, NEVER SOURCED. The one line this destination needs is read literally when the ping fires.
   # The last occurrence wins, as the read loop does today. Wrap the call so that a failed lookup, like a
   # failed curl, can never fail the backup.
   ping_url() { [ -f "$PING_FILE" ] || return 0
     awk -v k="PING_$(printf '%s' "$1" | tr '[:lower:]' '[:upper:]')=" \
         'index($0, k) == 1 { u = substr($0, length(k) + 1) } END { if (u != "") print u }' "$PING_FILE"; }
   ```
   - `container_for` and `volume_for` become one dest_row read. The one remaining
     `docker ps -a -qf name="$filter" | head -1` line keeps `-a`.
   - bin/restore-db:51-61 becomes `ROW=$(bash "$(dirname "$0")/../ops/backup-db.sh" --describe "$DEST")`.
   - **Why it is simpler.**
     - Four enumerations and one cross-file copy become one table.
     - The whitelist is not generated; it disappears. A destination has already passed the table check before its
       ping URL is looked up.
     - The warnings at :98-105, bin/backup-cron-install:194-204 and DEPLOY.md:715 have nothing left to warn about.
     - ops/backup-db.sh stays "THE definition" (its :2). It now also defines what a destination is.
5. Smallest credible implementation scope

  under a second of runtime. Not material.
- **Derive UNRAID_DESTINATIONS (test:55).** Its values are expected hostname stems. They are assertion data, not

- **A `kind` column (maker|sync) in the backup table** to replace backup-db:83, restore-db:71-74 and :257-281. Those

  "NO CODE HERE READS" (deploy.yml:130-135). OVH now uses LIBRARY_S3_* against R2 (deploy.ovh.yml:170-174). Worth

  deploy.yml:143 (env.clear deep-merges), and OPENSCAD_SIDECAR_URL is not restated. It is a second definition that
  would silently shadow a base change on two destinations, but it is two lines. Delete it opportunistically.
- **bin/sync-server state.** Its state is already explicit:
  - "Built" belongs to cargo's incremental build, or to TINKEREX_SYNC_BIN.
  - "Running" belongs to the caller: config/ci.rb:162-164 backgrounds it and sets a trap.

- **bin/secret's precedence and the preflight's outcomes.** bin/secret uses a non-empty export, else `op read`, else
  refuses an empty value. The preflight reports MISSING, EMPTY or ok (preflight:138-155). Both are already explicit

  against its own BACKUP_TZ default. After a deliberate BACKUP_TZ install that is a permanent false alarm, which §14i
  already documents. Writing the accepted zone into the marker comment would close it. This is real but latent, and
  a one-line contract change. Worth doing whenever the crontab line is next touched.
- **Enable Kamal's stock pre-build hook** (.kamal/hooks/pre-build.sample) so a dirty tree is refused rather than
  warned about (§14g). That adds a gate, and the stock sample also refuses unpushed commits. It is not a
  simplification.
- **ops/ci-runner-stack.yml.** The four services already share `<<: *runner`. What remains per service
  (container_name, RUNNER_NAME, work dir) cannot be removed without replicas. ops/kaneo-stack.yml,
  unraid/tinkerex.xml and the hook samples are static templates.
