## Opportunity 1: The harness owns the FileLayer memo's per-test lifetime -- one unconditional `FileLayer.reset!` in the shared teardown, and `pin_file_layer_backend` retired

1. Verdict: recommend

2. Evidence:
   - app/services/file_layer.rb:121-133 -- `attr_writer :current`, `def current; @current ||= build; end`, `def reset!; @current = nil; end`. One process-global memo that survives the per-test rollback. config/initializers/content_security_policy.rb:54 (`port = FileLayer.current`) resolves it on every response, so every integration request reads whatever the previous test in the forked worker left there.
   - test/test_helper.rb:243-257 -- the harness clears the memo only behind two flags: `if @file_layer_backend_pinned` (set only by `pin_file_layer_backend`, :233-241) and `if @fresh_share_library_roots` (set only by `use_fresh_share_library!`, :226-231). A direct `FileLayer.current = X` sets neither, so its reset is the caller's job. `grep -rn "FileLayer\.current *= " test/` -> 92 sites in 45 files (91 outside test_helper); `FileLayer.reset!` -> 158 occurrences in 99 files (S01's counts, re-measured).
   - The caller obligation is re-explained by hand in at least 16 files, e.g. test/integration/web/s3_delivery_test.rb:31-32 ("a direct `FileLayer.current =` does not set @file_layer_backend_pinned, so test_helper's teardown will not clean up after it"); test/jobs/library/scan_job_test.rb:244-247 ("without the reset! the adapter leaks into the next test in this forked worker and fails there as something unrelated, a whole debugging session away from the cause"); also share_delivery_test.rb:8-12, s3_write_test.rb:21-23, share_delete_test.rb:13-15, share_trash_test.rb:13-14, files_toolbar_test.rb:23-25, rescan_test.rb:14-17, trash_purge_job_test.rb:477, repo_history_flow_test.rb:265-266, repo_edit_flow_test.rb:539-540, system/measure_print_test.rb:23-26, measure_formats_test.rb:14-17, measure_export_test.rb:21-23, lbrn_measure_test.rb:14-17, code_viewer_test.rb:24-26.

   - Conditional resets that stay correct only while every assignment in the file remembers the flag: repo_history_flow_test.rb:255 and repo_edit_flow_test.rb:526, `teardown { FileLayer.reset! if @stubbed_s3 }`.

Its purpose -- pinning `chunk` for chunk-shaped fixtures, per its doc comment, which sits at test_helper.rb:104-114 above `port_upload`, 120 lines from the method -- went with Arc D Part 2 (27d1e0b0 "drop the chunk backend pins"). Its only 6 calls (project_discovery_job_test.rb:17, 37, 54, 93; model_intake_job_test.rb:13, 42) are each followed on the next line by `use_fresh_share_library!`, which reassigns the memo the pin just reset; the gates under test read `FileLayer.current.capabilities.scannable?` (app/jobs/maker/model_intake_job.rb:31, project_discovery_job.rb:55), never ENV. Meanwhile about 12 files carry a paragraph on why they do NOT use it (share_delivery_test.rb:8-12 and siblings), and test/system/README.md:26-27 tells system-test authors to "Pin one backend per test with `pin_file_layer_backend`". No system test does. On share it would build over the shared ambient LIBRARY_PATH, which test_helper.rb:200-202 names as the cause of cross-test clobber refusals.
   - History: the 2026-08-26 audit's S39-2 (`git show 07441e62:docs/AUDIT-2026-08-26-findings.md`) made `use_fresh_share_library!` own its cleanup (landed in cb50a9f0). It also proposed a block-form `with_file_layer(adapter)` for the direct assignments, and that half never landed: `grep -rn "with_file_layer(" test/` finds only library_broadcast_test's private `with_file_layer_env`.

3. Current complexity or invalid states: "An adapter that a finished test installed is still `FileLayer.current`" is a representable state. It is prevented only by convention at about 92 sites. The harness keeps three mechanisms with different teardown contracts for what production code sees as one act: a flag-guarded ENV pin, a flag-guarded fresh library, and a raw assignment with no contract at all. A missed reset fails in a different test, chosen by random order, in the same forked worker. The authors' compensations are themselves cost: defensive resets in `setup`, conditional teardowns keyed on unrelated ivars, about 16 copies of the same "load-bearing, not decoration" paragraph, and a near-dead helper that the system-test README recommends.

4. Proposed representation and why it is simpler: the memo's lifetime becomes "one test" by construction, so there is one rule with no flags and no call-site obligations:
   ```ruby
   # test/test_helper.rb -- replaces :233-257 (pin_file_layer_backend, both flags, both branches)
   # FileLayer.current IS PROCESS-GLOBAL AND OUTLIVES THE ROLLBACK, SO EVERY TEST ENDS WITH IT EMPTY.
   # Whatever a test installed -- use_fresh_share_library!, a direct `FileLayer.current =`, or the
   # ambient adapter a request built -- the next test in this forked worker rebuilds from ENV.
   teardown do
     FileLayer.reset!
     @fresh_share_library_roots&.each { |root| FileUtils.remove_entry(root) if root.exist? }
   end
   ```
   A raw assignment becomes exactly as safe as the helper. The 158 existing resets become redundant rather than wrong, because `reset!` is idempotent. `pin_file_layer_backend`, `@file_layer_backend_pinned`, `@file_layer_backend_prior` and the misplaced doc at :104-114 are deleted. If the s3-leg timing below shows a cost, there is a zero-rebuild variant: `setup { @file_layer_at_start = FileLayer.instance_variable_get(:@current) }` with `teardown { FileLayer.current = @file_layer_at_start }`. That is the shape library_broadcast_test hand-rolls, made harness-wide. It would change fresh_share_library_cleanup_test.rb:85 from `assert_nil` to `assert_same prior`.

5. Smallest credible implementation scope, in order:
   (a) test/test_helper.rb: the teardown above; delete :104-114 and :233-241.
   (b) A new harness guard, e.g. test/file_layer_memo_isolation_test.rb, built on the Probe pattern of fresh_share_library_cleanup_test.rb:23-52 (see 7).
   (c) Delete the 6 redundant `pin_file_layer_backend("share")` lines in project_discovery_job_test.rb and model_intake_job_test.rb.
   (d) test/system/README.md:26-27: name `use_fresh_share_library!` instead.
   (e) Fix the comments in the ~16 files from 2 that would now be false. Optionally drop the redundant reset line beside each, but never an adjacent `remove_entry` of a directory the file minted itself (the warning at test_helper.rb:220-225).

   No app/ change and no fixture change.

   - Rebuild cost: `S3.new` builds an Aws client eagerly (s3.rb:52, :1322) and the CSP header resolves the port on every response. So on the s3 leg, each port-touching integration test that does not already reset will construct one client. This is unmeasured and expected to be small. 3. Current complexity or invalid states: "signed in" is something a test believes rather than something it checks. A bare POST lets a test run every later request anonymously while it assumes it holds a session. That goes unnoticed when the test's own assertions are negative (404, no difference, count 0). It can be triggered by the per-IP throttle (more than 10 sign-ins inside one test), by an unconfirmed or passwordless fixture user (for example settings_hub_test.rb:33-36 `other_user!`, created with `omniauth_signup: true` and no password), or by any auth change. The check that makes the idiom safe exists at about 6 of 129 sites, and a destination change has to be found in each of them.

4. Proposed representation and why it is simpler: one owner, with the assertion that makes the session state known:
   ```ruby
   # test/test_helper.rb, ActionDispatch::IntegrationTest (beside bootstrap_account)
   WEB_PASSWORD = "correct horse battery staple".freeze

   # Signs `user` in through the real session door and FAILS HERE if it did not take. A failed
   # sign-in also redirects (Devise's FailureApp, the per-IP throttle); only the destination
   # (ApplicationController#after_sign_in_path_for) tells them apart.
   def sign_in_web!(user, password: WEB_PASSWORD)
     post user_session_path, params: { user: { email: user.email, password: } }
     assert_redirected_to root_path,
       "sign-in as #{user.email} did not take -- every later request in this test runs anonymously"
     user
   end

   # test/support/public_fixture.rb:100 -- 13 suites verify at once
   def sign_in_as(user) = sign_in_web!(user, password: PASSWORD)
   ```
   The distinct name is deliberate. A private `sign_in`/`sign_in_as` in a test class silently shadows a harness method of the same name, which is the collision S39-1 warned about.

## Considered and rejected
- **Consolidate the 18 byte-identical `replacing` definitions into test_helper.** Each copy carries a comment naming a different sibling (e.g. text_file_creation_test.rb:24-27, "there is no shared copy in test_helper.rb"). This is duplication only. I checked the hand-rolled variants for the dangerous restores:
  - Every `remove_method` site (library_broadcast_test.rb:80, chunk_remote_journey_test.rb:437, gerber_archive_test.rb:38, three_mf_manifest_test.rb:40/276, gerber_sets_test.rb:84/116, project_intake_test.rb:280, pins_test.rb:62) removes only a method it created.
  - The two `define_singleton_method(name, original)` restores of inherited methods (File.binread/binwrite in share_test.rb:100-116; Digest::SHA256.file in scanner_test.rb:354-358) leave permanent but behaviourally identical shadows.

  No live defect. It is a cheap rider on either recommendation since both edit test_helper, but it is not a finding.
- **A shared `count_queries`/`assert_constant_queries`.** There are 17 local copies with 4 filter spellings. In Rails 8.1 a query-cache hit keeps its own name and is flagged `cached: true` (activerecord .../abstract/query_cache.rb:333-345), so the `CACHE` exclusion in working_tree_test.rb:80 is dead. The only two copies that skip `payload[:cached]` (attach_to_project_test.rb:42, project_intake_test.rb:78) wrap the block in `ActiveRecord::Base.uncached`. That matters because load_defaults 8.1 sets `executor_around_test_case = true`, which runs every test with the AR query cache enabled. So all copies count equivalently for constancy, and no verdict changes.
  - The budget mechanism (page_query_budget_test.rb:47-73) is already reusable for a new page: a path, two seed lambdas, a label. The ~22 `add` lambdas are per-page seed knowledge, not copied scaffolding. A block form would only trim the `-> { add.call("s", SMALL) }, -> { add.call("l", LARGE - SMALL) }` boilerplate, which is cosmetic.
  - The large render's status is not asserted. A broken large page still changes the count and goes red, so this is not vacuous.
- **Backend-leg predicates.** Capability branches (31 sites) are the documented idiom, and every one I read is two-armed. `FileLayer.current.is_a?(FileLayer::S3)` (repo_history_flow_test.rb:268, repo_edit_flow_test.rb:542) and `ENV["LIBRARY_BACKEND"] == "s3"` (addons_controller_test.rb:64, library_output_test.rb:10) appear only to swap in a FakeS3 client. Opportunity 1 removes their reset obligations, and unifying their predicate is cosmetic. No idiom makes a test vacuous on a leg: the chunk_remote rigs `skip`, which counts as a run, so counts stay identical. The one dead claim found (readme_edit_test, below) comes from a share pin, not a leg predicate.
- **A harness-level FakeS3 for the ambient s3 leg.** This would change what the s3 leg measures. Today an accidental real S3 call fails loudly as Forbidden against `ci-not-a-real-bucket` by config/ci.rb's design. It would also carry §14e's "a fake that shares the code's misunderstanding" risk.
- **The ChunkRemoteJourney skip predicate's two spellings** (`ENV[...]` at chunk_remote_journey.rb:29 vs `LibraryBackend.name` at 3 sites). `LibraryBackend` is S01's finding. The canary's inline duplication is deliberate and documented (chunk_remote_journey.rb:7-22).
- **Platform differences in system tests.** Seven files measure against `documentElement.clientWidth`, which is correct on both platforms rather than a branch. One file branches on `matchMedia('(hover: hover)')` (projects_models_pages_test.rb:79). Forcing overlay scrollbars or emulated hover in the harness would hide the touch path the Linux runners exercise, which is a coverage loss.
- **About 15 hand-paired CDP viewport set/clear sites in 7 system files** (new_menu, home, phone_topbar, shell, files_selection, landing). This is the same shape as Opportunity 1, but every site restores in `ensure` or `teardown`. Adding `Emulation.clearDeviceMetricsOverride` beside the existing per-test `Network.clearBrowserCache` (application_system_test_case.rb:105-108) is an optional rider.
- **Running `assert_no_console_errors` automatically in teardown.** There are 166 explicit calls in 39 of 45 files, and 145 of them are the test's last line. Making the check automatic is a coverage change with an unmeasured blast radius (6 files never call it, and a mid-test failure would add a second, noisy one).
