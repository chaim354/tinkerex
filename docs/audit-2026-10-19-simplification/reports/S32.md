## Opportunity 1: Copy the `boxes` index entry with the `boxes` directory, so the snapshot has one owner per addon key

1. Verdict: recommend

2. Evidence:
   - Directory: all 18 `test/fixtures/addons/boxes/*.js` are byte-identical to `../tinkerex-addons/addons/boxes/`; `diff -rq` is clean, so upstream `bin/check-fixture-drift` passes today. Upstream boxes code last changed 2026-08-25 (d454a66), and the host mirror f86bf200 was committed in the same minute — the mirror discipline for the directory works.
   - Index entry: `test/fixtures/addons/manifests.json:14-22` vs upstream `addons/manifests.json:24-46`. The snapshot lacks `"min_host": 3` (upstream :31), `"layout": "wide"` (:35) and both `permissions` (:36-45); its `description` (:18) is test prose — "A SNAPSHOT of the real chaim354/tinkerex-addons boxes bundle, copied in verbatim, exercised here by test/system/{box_sections,tray_layout,tray_top_view}_test.rb …" — where the product says "Parametric laser-cut / CNC boxes" (:28).
   - It has never matched a published entry: unchanged since it was written in 6095b871 (2026-08-03), already without the `layout: "wide"` upstream declared that same day (bbd1d68); upstream then added `permissions` + `min_host: 1` (ba7ecb4, 2026-08-11) and `min_host: 3` (a9ff541, 2026-08-13). None was mirrored.
   - Nothing owns it. Upstream `bin/check-fixture-drift:18-25` compares bundle DIRECTORIES only and excludes the index on purpose; `:26-30` states the cost ("nothing in either repo asserts the version floor … no test anywhere would notice them disagreeing") and its premise: "`min_host` decides whether the /tools CARD greys out … which is equally why carrying it in the fixture would exercise nothing. Revisit if it ever gates more."
   - It now gates more. `app/controllers/tools/home_controller.rb:25` — `Maker::Addons::Registry.all.select(&:available?)` — drops an unavailable tool from New ▸ (8fc593ec, 2026-10-08, eight weeks after that comment), and two snapshot-backed tests assert the Box Generator is offered there: `test/integration/web/new_menu_test.rb:80-103` (`text: "Box Generator…"` at :99-100) and `test/system/new_menu_test.rb:22-33`.
   - The snapshot contradicts itself: the bundle it carries says "manifests.json declares `min_host: 3`" (`boxes/boxes.js:14-15`) and leans on that floor (`:115-117`), beside an index entry from which `Registry` reads `min_host: 0` (`app/services/maker/addons/registry.rb:230`).
   - The description is stale as documentation: it names 3 files, while 7 system test files drive `/tools/boxes` (box_sections, box_revisions, box_save_folder, tray_layout, tray_top_view, plan_export, new_menu) and `test/system/file_menu_test.rb:132-148` reads the entry's title. The trade-off it points at is stated in `box_sections_test.rb:4-23` and summarised in five other test headers.

3. Current complexity or invalid states:
   One index holds three ownership states: verbatim-upstream (`boxes/`), test-owned (`fixture`, `sdk-fixture`), and one hand-edited hybrid — the `boxes` entry — that neither repo's guard checks and that no deployment has ever served. Costs: (a) the system tests drive a `/tools/boxes` page no deployment renders — no permissions list (`app/views/tools/addons/show.html.erb:16-25`), no `container-wide` (`:10`); (b) every snapshot-backed availability decision (New menu, gallery) sees `min_host: 0`, so the fact upstream concedes nothing asserts — the host under test satisfies the floor the shipped bundle declares — cannot be asserted from this suite even in principle; (c) the upstream guard carries a 13-line exception (`:18-30`) whose premise is now false; (d) the description doubles as documentation and has gone stale.
   No current test outcome depends on the difference (verified by reading, not by running): `Host::LEVEL` is 3 (`app/services/maker/addons/host.rb:34`), so `min_host: 3` keeps the addon available; `container-wide` only lifts `max-width: var(--container-max)` = 1360px (`app/assets/stylesheets/shell.css:120-121`, `application.css:71`), and at the system-test window (`test/application_system_test_case.rb:6`, 1400px) the 216px rail leaves a main column of at most 1184px, so the width/height-measuring tests (`box_sections_test.rb:390`, `:443`) cannot see it; of the permissions only `library:read` is enforced (`docs/invariants/addons.md:572`, `Tools::AddonsController#file`), which neither copy declares and the bundle never needs (no `files.read` anywhere in `boxes/*.js`); `AddonOrigins#addon_origins_for` (`app/controllers/concerns/addon_origins.rb:37-49`) reads `Registry.all` unfiltered, so file_menu's label is unaffected; and no snapshot-loading test asserts the boxes subtitle or a permissions list.

4. Proposed representation and why it is simpler:
   One rule, keyed by addon: a key whose directory is copied from tinkerex-addons (`boxes`) has its index entry copied with it, whole; keys that exist only here (`fixture`, `sdk-fixture`) stay test-owned and say what their tests need (their omissions are load-bearing — e.g. `fixture` declaring no `library:read` is the negative case of `addon_sdk_test.rb:335`).
   ```json
   { "key": "boxes", "title": "Box Generator", "icon": "(as upstream)",
     "description": "Parametric laser-cut / CNC boxes", "api_version": "1", "entry": "boxes.js",
     "min_host": 3, "services": [ "boxes" ], "layout": "wide",
     "permissions": [ { "name": "library:write", "reasoning": "…" },
                      { "name": "service:boxes", "reasoning": "…" } ] }
   ```
   (upstream `addons/manifests.json:24-46`, copied verbatim.) Simpler because "the boxes snapshot" becomes one copied unit — directory plus entry — instead of "the directory but not its index row". The upstream guard can then compare each snapshotted key's entry whole, which is neither the file equality it rightly rejects (the synthetic entries would fail it) nor the "chosen SUBSET of keys" it rightly rejects (`check-fixture-drift:22-24`); its exception and its admitted blind spot both go. The description's documentation job is already done by the test headers.

5. Smallest credible implementation scope:

Without step 2, step 1 still removes the hybrid and the self-contradiction, but the entry can drift again the way it did three times.

## Considered and rejected

- **Trim the 2,710-line boxes copy to what the tests touch.** All 18 modules are in `boxes.js`'s static import graph (boxes → gallery, editor, show; editor → sections, tray_sync, top_view, preview, fields, export, folder_field, history; export → plan, sheet, pdf; plan/tray_sync/top_view → tray_layout; gallery/fields → util), so a missing module fails the entry import and the page reads "This tool failed to load". Every module is exercised: gallery/sections/filter/util by `box_sections_test.rb:148-226, :443` and the rail tests in `box_revisions_test.rb`; editor/fields/preview by `box_sections_test.rb:228-372, :390`, `box_revisions_test.rb`, `tray_layout_test.rb:103`; folder_field by `box_save_folder_test.rb:51`; history and show by `box_revisions_test.rb:106, :225`; tray_sync/tray_layout by `tray_layout_test.rb` (5 tests); top_view/plan by `tray_top_view_test.rb` (5) and `plan_export_test.rb`; export/sheet/pdf by `plan_export_test.rb` (module imports :50-325, UI :327-410). A reduced copy would also fail upstream's `diff -r -q` (`check-fixture-drift:52`) and test a bundle nobody ships.
- **Point the tests at `../tinkerex-addons` instead of a snapshot.** Recorded rejection (`docs/invariants/addons.md:222-232`; `box_sections_test.rb:19-23`): zero coverage on a fresh clone or a runner without the sibling.
- **Own the drift guard here — a CI step that clones tinkerex-addons and diffs.** A blocking gate on another repo's `main` turns every upstream push into a host-wide red, the shape CLAUDE.md §14e records for brakeman's `--ensure-latest` (a gate reports on the code, never on how current an upstream is); a skip-when-absent variant is vacuous (§14e, "a guard that skips on the thing it asserts"). Publish time upstream, with both trees present, stays the right owner for the directory comparison.
- **Stamp the snapshot with the upstream SHA it was copied from.** A second representation of what `diff -r` already answers exactly, free to disagree with the content — upstream's own `bin/build-push:28-29` refuses that ("two provenance stamps that can disagree are worse than one").
- **Make the snapshot a git submodule or subtree.** `Source::Local` reads one root with one `manifests.json` that must also hold the two test-owned addons; a non-recursive clone gets nothing; it reverses a recorded design to replace a copy that is currently exact.
- **Delete or update `fixture/save.js`** (a drifted raw-ctx copy of the save dance the SDK absorbed). Recorded keep (`docs/invariants/addons.md:296-310`, `fixture/fixture.js:22-26`): `fixture` holds the raw-ctx half of the compatibility rule, and the flat 409 body save.js reads is the shape pre-SDK bundles still depend on; neither file is the other's guard.
- **Merge `fixture` and `sdk-fixture`.** The split is the compatibility rule itself (raw ctx vs SDK, `manifests.json:27`); each has one owning test file.
- **Drop `fixture`'s `services: ["fixture-svc"]`, which `fixture.js` never calls.** Misleading on its face, but it has a named consumer — the negative case of `test/integration/web/new_menu_test.rb:76-79, :101` — and moving that role to `sdk-fixture` is a test edit for no structural gain; the visible consequence is template_hygiene's (note below).
- **Centralise how tests point at the snapshot.** 14 copies of `Rails.root.join("test/fixtures/addons").to_s` in 13 test files, five identical `SAMPLE_404` regexes, six identical ENV + `FakeBoxesSidecar` setup/teardown pairs — but that is the tests' code, not the snapshot, and the gain is line count.
- **Derive the bundle CSS-class contract from the snapshot.** Real (first note below), but the guard would live in the design-system tests, not in this boundary.
