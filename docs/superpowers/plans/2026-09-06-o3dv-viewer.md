# The 3D viewer on Online3DViewer — implementation plan

> **For agentic workers:** execute per `.claude/commands/execute-plan.md`. One implementer, one
> capped review. Stacked on `claude/gerber-preview`.

**Goal:** replace the hand-rolled Three.js viewer (`modelviewer_controller.js`: STL, 3MF, OBJ) with
Online3DViewer's embedded viewer so the file page and the model page can show every format its
importers read — glTF/GLB, PLY, OFF, DAE, WRL, 3DS, FBX, 3DM, AMF, and STEP/IGES/BREP/FCStd through
its OpenCascade importer — and give the new mesh formats server thumbnails through the F3D renderer
the image already ships.

**Architecture:** the same vendoring rule as KiCanvas and tracespace — ONE vendored build of
`online-3d-viewer@0.18.0` (MIT), `bin/build-o3dv` copying the package's `build/engine/o3dv.module.js`
into `vendor/javascript/o3dv.js` and its `libs/` (the WebAssembly importers) into
`public/o3dv/<version>/`, one importmap pin with `preload: false`, and the EXISTING Stimulus
identifier `modelviewer` with the EXISTING data contract (`url`, `format`, `lazy`; targets
`canvas`, `dims`, `fallback`, `source`; actions `load`, `reset`, `fullscreen`, `showPoster`,
`selectSource`) so every template and every test that pins that markup keeps its meaning. What
changes is the engine behind `load()`: `OV.EmbeddedViewer` over the named blob route (the library
infers the format from the URL's trailing extension, so the URL carries the real filename, the
KiCanvas rule). **The `three` pins stay**: `chaim354/tinkerex-addons`' openscad addon
dynamic-imports `three`, `three/addons/controls/OrbitControls.js` and
`three/addons/loaders/3MFLoader.js` through the host importmap (verified 2026-09-06), so those
three pins plus `three-core` and `fflate` are an addon contract; only `STLLoader.js` and
`OBJLoader.js` — imported by nothing but the old controller — are retired.

**Licences (§9):** online-3d-viewer MIT; three MIT; fflate MIT; draco (glTF decoder) Apache-2.0;
rhino3dm MIT. **occt-import-js is LGPL-2.1** (the STEP/IGES/BREP/FCStd importer): a separately
shipped WebAssembly file the browser fetches at runtime, never linked into our code — the same
posture the image already takes for OCCT inside the F3D subprocess (`Dockerfile`, "OCCT is LGPL and
stays process-isolated"), and the LGPL's own dynamic-use case. Its licence text ships beside the
wasm. **web-ifc (MPL-2.0, the IFC importer) is NOT shipped**: IFC is not a maker format and MPL is
file-level copyleft we have no reason to carry; `.ifc` is simply not in the viewable list.

### A.1 The build

`bin/build-o3dv`: temp dir, `npm init -y`, `npm install --silent online-3d-viewer@0.18.0`, copy
`node_modules/online-3d-viewer/build/engine/o3dv.module.js` → `vendor/javascript/o3dv.js`, copy
`node_modules/online-3d-viewer/libs/*` → `public/o3dv/0.18.0/` (keep only what the shipped
formats need: `occt-import-js.{js,wasm}`, `draco_decoder.{js,wasm}` if present, `rhino3dm.{js,wasm}`;
NOT `web-ifc-api*`), copy the package LICENSE → `vendor/javascript/LICENSE-o3dv.md` with the
occt-import-js LGPL text appended under its own heading, print sizes. Verify the module is
self-contained (it must not `import "three"` bare — if it does, the pinned three 0.185.1 would be
loaded beside its own expectation of 0.176; report and, if so, prefer the package's
`build/engine/o3dv.min.js` IIFE wrapped in a tiny ESM shim, or a rollup of `source/engine/main.js`).

### A.2 The controller

Keep the file, the identifier, the values, the targets and the action names. Internals:

```js
async boot() {
  const OV = await import("online-3d-viewer")
  OV.SetExternalLibLocation("/o3dv/0.18.0")       // where the wasm importers live
  this.viewer = new OV.EmbeddedViewer(this.canvasTarget, {
    backgroundColor: new OV.RGBAColor(0, 0, 0, 0), // the stage's own background shows through
    defaultColor: new OV.RGBColor(200, 200, 200),
    edgeSettings: new OV.EdgeSettings(false, new OV.RGBColor(0, 0, 0), 1),
    onModelLoaded: () => this.loaded()
  })
}
load()   → boot() once, then this.viewer.LoadModelFromUrlList([this.urlValue])
loaded() → dims from this.viewer.GetModel().GetBoundingBox() (or GetViewer().GetBoundingBox()),
           rendered as "x × y × z mm" like today; poster hidden, stage shown
reset()  → this.viewer.GetViewer().SetUpVector(OV.Direction.Z, true); FitModelToWindow(true)
fullscreen()/showPoster()/selectSource() as today
```

Read the package's `source/engine/viewer/embeddedviewer.js` for the real API (`EmbeddedViewer`,
`LoadModelFromUrlList`, `GetViewer`, `GetModel`, `Resize`) and `source/engine/main.js` for what the
module exports; the names above are from 0.18's README and may need adjusting. Z-up: the old
controller rotated STL/3MF to Z-up per format (`UP_AXIS`); OV's `SetUpVector` does the same job
once — keep the per-format table if OV's default reads as lying down for STL. Failure stays the
old contract: any error → the poster + download fallback, `data-modelviewer-state="failed"`.

### A.3 The vocabulary and the thumbnails

`Maker::FileAttachment::VIEWABLE_3D_EXTS = %w[stl 3mf obj gltf glb ply off dae wrl 3ds fbx 3dm amf step stp iges igs brep fcstd].freeze`
(what the shipped importers read; `fcstd` and the CAD formats need the occt wasm). `ROLE_BY_EXT`
gains the mesh ones as `model` (the CAD ones that are already `cad_source` stay `cad_source` — a
role is where a file FILES, not whether it renders). `ModelsController` and `FilesController` read
the shared constant. The registry gains the F3D-readable ones → `Maker::Previews::Mesh`; read that
renderer's contract test (`renderer_contract_test.rb`) and the registry test, and follow
`files-preview.md`'s "ONE file-type vocabulary" rule (the thumbnail poll must keep answering for a
node with no row).
